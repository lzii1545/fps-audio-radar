# FPS 可视化脚步器

帮助听障玩家「看见」声音方向的开源工具：实时把游戏中的脚步声、枪声等声音事件，
以**雷达**或**屏幕方位图标**（手游式）两种方式显示在置顶覆盖层上。

## 功能

- **两种显示模式**：扇形网格雷达（近/中/远三层 × 可调扇区，事件在对应格子内显示图标）/
  屏幕方位图标（像手游一样在对应方向直接显示），也可双显，模式一键切换
- **图标化显示**：脚步（奔跑人形）/ 子弹图标为内嵌 SVG 矢量绘制，任意大小清晰、
  颜色跟随设置；屏幕方位模式下图标按方位旋转、尖端朝外
- **防刷屏**：连续同类事件按扇区宽度自动合并为一个跟随滑动的指示；脚步/枪声各自
  独立的数量上限（默认 5+5，可调 1~10）与保留时长（默认 1.5s/2.5s）
- **声音位置测试**：任意角度 360°、近/中/远一键注入测试事件，立即在覆盖层验证显示
- **位置拖拽定位**：进入调整模式后全屏灰色遮罩，直接拖动元素摆位置（雷达中心 / 方位中心 /
  方位环半径）；设置面板实时预览里也可以直接拖动定位
- 所有元素独立可调：大小、位置、透明度、颜色、扇区数（8/12/16/24）
- 可视化设置面板：无边框窗口、自绘控件与动效、设备选择、VU 电平表、实时双模式预览、
  配置自动保存
- 立体声 / 多声道自适应：多声道（5.1/7.1）可分辨 360° 方位；立体声仅能分辨左右
- 测试回放模式：设备列表选「（测试）WAV 回放」可直接用 test_sound.wav 验证全链路（无需声卡）

## 快速开始

1. 构建：`tools\build.ps1 build --release`（产物 `target\release\fps-audio-radar.exe`）
2. 运行后在「检测」页选择输出设备（默认「（默认输出设备）」即可）；
3. 游戏内切换为【无边框窗口】模式（独占全屏会挡住覆盖层）；
4. 「位置」页 → 进入位置调整模式 → 把雷达中心拖到准星位置 → 点 ✓；
5. **推荐**：安装 7.1 虚拟声卡（VB-Audio / Voicemeeter 等），让游戏以 7.1 声道输出到该
   虚拟设备并开启监听（自己照常听到声音），再在面板选择该设备 → 获得前后 360° 方位。

## 参数说明（节选）

| 参数 | 说明 |
| --- | --- |
| 主增益 | 输入整体放大倍数，声音小的游戏可调大 |
| 触发阈值 | 高于噪声地板多少 dB 才判定为事件，环境嘈杂可调高 |
| 自动噪声地板 | 前 1 秒取最小能量初始化，之后缓慢追踪环境底噪（推荐开启） |
| 方向平滑 | 同类连续事件间方向平滑度，越大越稳、响应越慢 |
| 脚步频段 / 增益 | 各游戏脚步声音色不同，按游戏微调（CS2 一般 60–450 Hz） |
| 枪声高频起点 / 增益 | 枪声判定依赖宽带高频分量与急促起音 |
| 脚步/枪声数量上限 | 同类事件同屏最大数量（默认各 5，可调 1~10） |
| 脚步/枪声保留时长 | 事件渐隐时间（默认 1.5s / 2.5s） |
| 扇区数 | 雷达扇形网格的扇区数量（8/12/16/24），也是同类事件合并的方位粒度 |
| 雷达半径 / 图标大小 / 环半径 | 两种模式的尺寸 |
| 显示模式 | 0=雷达 1=屏幕方位 2=双显 |

## 构建要求（本机已验证）

- Windows 10 / 11
- Rust gnullvm 工具链：`rustup toolchain install stable-x86_64-pc-windows-gnullvm`
- mingw 导入库：`rustup toolchain install stable-x86_64-pc-windows-gnu --profile minimal --component rust-mingw`
- DirectX/shlwapi 别名库：`tools\mingw-libs\`（由 windows-targets 分区库复制而来，已入库）
- 链接配置见 `.cargo\config.toml`，构建脚本 `tools\build.ps1`

> 注：本机没有 MSVC，故采用 gnullvm + rust-lld 方案。若你机器有 Visual Studio，
> 直接 `cargo build --release`（MSVC 工具链）即可，无需上述配置。

## 已知限制

- 立体声设备只能分辨左右（±90°），前后需要 7.1 虚拟声卡方案；
- 距离为相对响度估计，按近/中/远三层显示；
- 独占全屏模式下覆盖层不可见，需使用无边框窗口模式；
- 分类为轻量启发式算法（频带能量比 + 起音速度），复杂音景下可能误报，后续计划接入 ONNX 模型；
- 若输出设备带自动增益/动态增强（如部分音效增强软件），可能干扰事件切分，
  建议采集直通设备（虚拟声卡）。

## 目录结构

```
src/main.rs      入口：DPI/COM 初始化 + 三线程（音频采集 / 覆盖层 / 设置面板）
src/audio.rs     WASAPI Loopback 采集、设备枚举、格式协商、测试 WAV 回放、测试事件注入
src/detect.rs    事件切分、方位计算、脚步/枪声分类、噪声地板、同类事件合并
src/overlay.rs   置顶透明点击穿透覆盖层（纯 Win32 + ULW 呈现 + tiny-skia 绘制）
src/app.rs       设置面板 UI（egui + wgpu，无边框自绘组件）
src/settings.rs  参数定义与持久化（%APPDATA%\FPSAudioRadar\settings.json）
src/state.rs     线程间共享状态
src/svg.rs       内嵌 SVG 路径解析与图标渲染（脚步/子弹图标）
tools/           测试工具（测试音生成、端到端测试、截图分析等）
```
